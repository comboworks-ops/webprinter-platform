# Checkout server quote coverage — 2026-09-08

The local creator now verifies STORFORMAT prices from the same stored inputs and formula used by the current storefront. Generic products labelled `matrix`, `fixed` or `rate` can also check out when `pricing-read` returns one exact stored price for the requested tenant, product, quantity and selection. Fixed, per-quantity and per-area option extras are verified before a PaymentIntent is created. No catalog prices, existing storefront formula or POD v1/v2 calculations were changed by this server work.

This supersedes the initial payment repair's blanket hold on STORFORMAT, fixed/rate labels and per-area options. It does **not** make incomplete product configurations purchasable. The creator remains disabled unless the existing checkout release and webhook environment requirements are fulfilled. No function or migration was deployed and no hosted payment, Storage write or supplier call was made.

## Exact pricing contract

- STORFORMAT uses `src/utils/storformatPricing.ts`, which the actual `StorformatConfigurator.tsx` calls. A deployment-local copy lives at `supabase/functions/_shared/storefrontStorformatFormula.ts`; a test compares its complete formula body byte for byte with that source. This intentionally does not use the separate, simplified newer storformat utility.
- `storefrontStorformatQuote.ts` loads config, materials, finishes, products and their pricing rows for the exact product **and** tenant. Reads paginate in stable order; incomplete/failed reads cannot silently produce a cheaper price. Primary tier rows precede the same legacy material/finish/product fallbacks used in the frontend. The linked backend has no `storformat_product_m2_prices` table: only a known missing-table error for this optional fallback is tolerated, and a selected item without any usable price still fails.
- Browser `checkout_quote.storformat` sends `{widthMm,heightMm,materialId,finishIds,productIds,selectedSectionValues}`. The server resolves the stored layout and requires every charged selection to match it. Required choices cannot be omitted; optional choices may be empty; free visual choices stay price-neutral as in the existing component. Unknown section/value IDs, duplicate/injected components, unavailable quantities, invalid dimensions or material limits without splitting fail before payment. The immutable quote snapshot records verified dimensions and source `storformat_existing_formula_v1`.
- Existing tier matching, interpolation anchors and tier/item/global markups are preserved, including the current formula's inclusive boundaries and fallback semantics. Fixed finishes multiply the unit charge by quantity. Fixed products add their initial charge to the exact stored quantity price. A partial fixed-product quantity table cannot silently price an absent quantity at zero. Initial-charge-only products remain supported.
- Generic `matrix`/`fixed`/`rate` labels require exactly one returned generic price row; no quote is invented from disconnected global legacy rates. The matched product must be published in the requested tenant. There is no fallback to another tenant or to the browser's total.
- Fixed options add their stored price; per-quantity options multiply it by quantity; per-area options multiply it by verified area and quantity. All option groups must be assigned to the product. For generic rows, the format must belong to that product/tenant, its group must have `kind='format'`, and its ID must be attached to the matched price row. Stored millimeter dimensions supply area; browser width/height/area are consistency hints. STORFORMAT uses its verified custom dimensions. Unknown generic/custom format dimensions still fail closed for per-area charges.
- The checkout money boundary mirrors `ProductPricePanel`: round the product price and option extras independently to whole DKK, then add the selected shipping charge. Shipping matches the actual checkout's `resolveDeliveryMethodCost` (explicit rounded charge, otherwise standard 49 / express 199); that helper ignores the subtotal. The creator now sends `Cache-Control: no-store` for its own JSON responses.

The parent frontend repair supplies the new transport fields and fixes dimension-known per-area extras to use exact format metadata. See the combined repair report for its tests/browser evidence.
